## Fair comparison and treatment

Use C (direct source), P (explicit simple evidence/condition process), G (generic
ordered source rows), H (actual v1 CG-04 integration from the same ordinary prose),
and H-new (identical policy/source/scenario/case input with only checked state
removed). Every arm receives the same task, seven output fields, all preference,
condition and conflict labels, and the same statement naming convention. Neither
gold nor the authored expected answer is sent to any model. H's checked state is
the treatment produced by the real runtime, not injected gold.

Every H case passes package equality, source anchoring, grounded preferences,
actual applicability/revision/conflict checks, checked-state inclusion and H-new
removal. Final inputs differ solely by checked state. Across the four cases, the
package covers actual condition execution, other-scope preservation, explicit
local supersession, unresolved conflict and attribution. Preflight also checks
independently authored gold against the checked source. Rerun this provider-free
preflight on the owner-authorized exact main before paying. Failure blocks paid
execution and requires generic engineering repair and a new freeze; never edit
gold/questions to force a pass.

The seven-field scorer compares preference_states, condition_states,
superseded_ids, conflict_state, global_value_ranking, moral_winner and
choice_implies_enduring_value. Dict keys and nested types/values must match;
superseded IDs use source order. Invalid JSON or extra/missing top-level fields
score zero; otherwise each exactly typed matching field scores one, 28 per arm.
Full-case correctness requires all seven. Source-first semantic review is
decisive, including whether a strict field error reflects a real boundary error
or merely a measurement defect.
