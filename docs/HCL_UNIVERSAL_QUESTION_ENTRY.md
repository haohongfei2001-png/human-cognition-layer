# Ordinary questions through HCL planning and current retained capabilities

`UniversalHCL` is the new external library entry for a plain question, instruction
plus supplied source, or multiple supplied sources. It does not require the caller
to invent a source document for a question such as “分析人类社会”. Every admitted
request uses internal planning, capability execution/explicit insufficiency,
composition and answer/source review. There is no Base shortcut.

## Original implementation and limits

The catalog reconciles all 40 runtime A–H packages with real callable retained
implementations; A00 is governance. This corrects the older 28-entry v1 inventory.
Catalog membership is not a claim that every family has a general-input adapter.
B01/B02/C01/C03 reuse the source reader. C02 uses the current competing-explanation
workspace and G02 uses the current responsibility-composition workspace. G01 uses
the existing normative-premise workspace, taking possible caller conditions only
from the original request, even when no source is supplied. It prepares premises,
not a responsibility verdict. [G01 contract and limits](HCL_UNIVERSAL_NORMATIVE_ENTRY.md). Other
selections return explicit adapter/prerequisite limits. The planner is a bounded
model interface, not a hidden external regex gate or a claimed solved language
understanding system. It receives the original question and current catalog,
selects at most three operations, and cannot create arbitrary executable code.

With no supplied source, selected source-bound operations remain unavailable.
The answer can still provide ordinary conceptual analysis or model knowledge,
explicitly tagged `UNSOURCED_MODEL_KNOWLEDGE`. Its citations must be empty. This
classification does not make the content verified truth, and does not mean all
retained capabilities have executed. In source-backed tasks, the original query,
complete original source text, source identity and version survive composition.
Total source/context bounds refuse rather than silently truncate or omit sources.

Actual planner quality is unverified. Scripted planner/answer ports in tests only
validate interface control flow, real retained checkers and failure behavior.
There is no provider transport, credential, live grant, model call, runtime
activation in another product, or empirical efficacy claim in this package.

## Source and premise boundaries

A planned actor binding needs an exact quote, source ID and Unicode character
start in one of its selected sources. Unknown IDs, invented anchors, extra schema
fields and oversized plans are rejected before answer delivery. Planned question
adaptations remain interpretations beside the original request, never new facts.
G02 reads adopted rules only from the original user request, never a rewritten
planner question. Ingestion timestamps are actual receipt time, not invented
story-event dates. Temporary G02 workspaces preserve shared source revisions;
C02/G02 result support remains linked to the shared original source roots.

Source revisions, withdrawn source roots and invalidated selected support claims
are checked before final composition/call and after the answer returns. Raw final
output is retained separately from deliverable output. Invalid citations, stale
support or unsupported output schema block delivery without rewriting the raw
model answer. Exact references remain semantic-uncertified. General inference,
reported causes and conditional explanations are not replaced with blanket refusal.

## Call accounting and transport contract

Every call is explicit: one planning phase and one answer phase, maximum two.
There are no extraction/judge subcalls or retries. A caller supplies both metered
ports and an explicit allowance/reference; otherwise the receipt says unavailable
and no plan is pretended complete. Live ports additionally require a durable
journal callback. It must persist the reservation before `complete` is invoked.
The quote callback must be local, bounded and transport-free; a real provider port
must enforce its quoted token/model/rate bound, timeout and cost accounting.
Those adapters, actual host durability/restart reconciliation and any new paid
authorization remain separate work. A callable journal is a required host contract,
not proof that the caller implemented disk durability or recovery correctly.

Admission is rechecked atomically after the reservation callback, and phase
execution is single-flight. Reserved attempts, actual backend invocations and
provider invocations are separate. A failed journal produces no transport call;
a thrown transport retains its reservation and unknown status, closes the
allowance and is not retried. The journal stores only fixed safe states and
allowlisted nonnegative integer token counts, not raw exceptions, arbitrary usage
metadata, credentials or reasoning text. Output lengths are bounded before parsing
or receipt retention. Any later caller must not recycle a closed grant.
