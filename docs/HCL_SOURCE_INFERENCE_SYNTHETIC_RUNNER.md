SQLite FULL synchronous commits persist each slot reservation before transport.
A separate OS lock prevents two local writers. Successful receipts retain raw
provider response, returned model, usage and the request digest. An ordinary
transport exception records only its type, never potentially credential-bearing
exception text. A crash after reservation conservatively leaves the outcome
unknown: resume refuses that slot and all subsequent calls. It does not retry or
reclaim the reservation. A fully persisted successful prefix can resume on the
same ledger and invocation identity. A completed ledger never calls again.
Malformed usage or unexpected model stops the run and preserves raw response.
Format-invalid/truncated answers remain in their original slot without regeneration;
valid bounded usage permits the other predeclared slots to continue.

The workflow refuses any run attempt except 1 and requires the complete workflow
run count to be exactly one, matching its own ID and SHA. A second push, replay,
manual rerun, pagination ambiguity or uncertain run inventory blocks transport.
Concurrency also serializes duplicate invocations. Resume is local to a retained
ledger, not permission to start a new workflow. Lost artifacts or an interrupted
runner do not authorize a new invocation; all possibly attempted reservations
remain consumed. Upload runs even on failure, but catastrophic host loss can still
prevent artifact delivery. No success or cost can be inferred from missing receipts.
