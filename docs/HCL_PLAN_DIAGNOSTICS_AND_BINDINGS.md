# Safe failure stages and exact-quote actor bindings

The October 8 smoke returned a planning response but produced no native operation
or final answer. Its frozen exporter retained a broad failure category, so the
specific rejected field cannot be recovered. This provider-free change makes
future runtime failures distinguishable without disclosing source text, planner
responses, provider exceptions or hidden reasoning. It does not attribute that
historical failure to an offset or any other particular model mistake.

Failed orchestration receipts now retain a code-owned failure stage beside their
existing safe failure reason. Malformed planning JSON gets INVALID_PLANNING_JSON;
a valid empty plan still fails NATIVE_HCL_RESULT_REQUIRED_BEFORE_ANSWER after
native-result admission. Planning validation, entry admission, native dispatch,
native-result admission, final-context construction, final-provider admission and
final-response validation are distinct bounded stages. The reusable
safe_orchestration_failure_details projection emits only allowlisted enums and
falls back to UNKNOWN/ORCHESTRATION_FAILURE for unrecognized values. It is
diagnostic metadata, never proof of correct interpretation or useful treatment.
Historical frozen exporters and their published evidence remain unchanged.

Actor bindings may omit start only when their exact quote has exactly one
occurrence in the named selected source. The validator resolves that occurrence
before native dispatch and final composition. It counts overlapping matches and
uses Python Unicode character positions. Explicit offsets must match exactly;
null, booleans, negative or noninteger offsets are rejected. It never repairs a
supplied mismatch, trims or normalizes text, changes source identity, guesses an
actor alias, or searches another source. Repeated quotes require an explicit
correct offset. Other binding keys and existing bounds stay strict.

The existing G02 adapter consumes the canonical binding and complete original
source. Its original-user-only rule authority, distinct actor/episode rules and
native bounds remain. Successful anchoring does not certify responsibility or
create checked treatment. Semantic-candidate parsing is unchanged. Source
revision/withdrawal guards, ordinary limited-evidence answers and strict native
treatment before final generation remain in force. A bad later binding prevents
all dispatch, including an earlier otherwise valid operation.

The revised binding instructions and G02 description together reduce fixed
planning-request overhead by five bytes. The full 36,000-byte transport ceiling
and refusal on oversized complete contexts remain. Planning stays 16,384/high,
final answering 16,384/low, with no new provider phase or retry. Canonical bindings
can include a derived start; final requests still receive the full unmodified
source and remain subject to the same size checks.
