# E05 — Relationship, identity, role and value dynamics

## CAPABILITY_DELTA

A correction to knowledge/control/stated-intention evidence changes two dependent
interpretations together: the explanation of the failure cited in a relationship
judgment, and the explanation of a source-bound role failure. Neither change
rewrites the reported attitude, identity or preference. Another domain's result
remains identical without reexecution. This is an actual cross-operation join and
update, not four independent tables.

`prepare_relationship_dynamics` reuses E01/E02, E03 and E04 in one shared semantic
workspace. A role failure requires an explicit narrator episode link and one
matching negative behavior. A relationship explanation requires the assessor's
actual cited reason to name that failure. Missing/ambiguous links remain unresolved.
Conditional hypotheses keep factor support and counterevidence; there is no unique
actual cause or moral verdict. Preference/choice changes are represented separately
and never silently bound as the cause of this failure.

`RelationshipDynamicsWorkspace` caches source/query/observer results. Explicit
analyst correction versus appended disclosure produces a labeled comparison of
analyst snapshots. Character change is not inferred. Access changes suppress prior
snapshot comparison, and stale source/support refuses final input. Shared evidence
invalidation propagates through real operation dependencies. Independent documents
remain independent; no cross-document person identity is inferred.

The simplest alternative is independent source tables and manual comparison.
Simplify the joins if later serious evaluation finds their coordinated revision
adds no utility over a generic scaffold.
