# Preserve each ordinary reader's native policy

This is a lossless contract-information repair for existing B01/B02/C01/C03
ordinary reader results. It adds no adapter, inference mechanism, provider phase
or model-efficacy claim.

## Defect and source of authority

The non-translated reader branch retained the native user JSON but omitted the
native system contract. For an actual B01 nested denial, the missing text included
the distinction between outer and inner denial, limits on projecting a nested
attribution into another person's actual state, and the source-order/time boundary.
All four positive reader fixtures returned real selected-family treatment and
the complete native JSON, while their code-owned policies were absent.

The branch now copies `entry.messages[0]['content']` into `preparation_policy`
beside **that operation's** unchanged result, matching the existing conditional
reader representation. The value comes only from the versioned retained-reader
code's system message. It is not extracted from source text, the model's plan,
a result's arbitrary same-named field, or a caller-provided policy.

The expanded receipt retains each complete policy beside its own result. The final
wire shares a pair only when the complete policy, complete native result and the
ordinary call's question/source selection/bindings match exactly. Only executed
ordinary B01/B02/C01/C03 reader rows qualify; translated or unavailable results
do not. Each referring operation keeps its own capability, treatment and support
metadata and a code-generated index into `native_reader_contexts`. No source or
planner field can create that table or a reference. A strict test-side expansion
recovers every original field exactly without changing the receipt.

Policies are not installed as new top-level system messages or combined into a
new global policy. The existing final source/citation contract remains exact;
two short code-owned instructions explain policy scope and, when sharing occurs,
reference lookup. A native policy applies only to its associated result and
cannot override original-source authority or final citation rules. Source and
planner strings remain data; extra operation policy fields are still rejected.

## Preserved behavior and costs

- Native result JSON, source IDs/text/versions, operation order, support claims,
  source-snapshot checks and exact citation validation remain unchanged.
- Multiple operations retain exact result/policy associations, including separate
  treatment flags when they share an identical underlying reader result.
- Raw final answers are still accepted or rejected unchanged; no repair, retry,
  additional model call or Base substitution is introduced.
- Policies are not shortened or discarded to fit transport. Complete requests
  still stop at 36,000 UTF-8 bytes; preserving previously omitted text can increase
  request size. No smaller-token, lower-cost or higher-delivery-rate claim follows.

## Provider-free verification and history

Twelve new test methods cover the four positive readers, nested denial/time
boundaries, source/planner reserved-key forgery, multiple policy association,
source revisions, exact citations/raw output, an actually oversized nonduplicate
request, exact shared-pair reconstruction and distinct scope/value/type cases that
must never be shared. The initial nine policy tests exposed eleven absent-field
subtest errors on the exact prior runtime. These are authored wiring/security
checks, not model instruction-compliance or answer-quality evidence.

The existing C02 plus two ordinary-reader fixture was 35,749 bytes before this
repair. Naively retaining both missing policies made it 37,085 bytes. Their
policies (640 characters each) and result JSON (2,334 serialized bytes each) match
exactly. Complete pair sharing, including the new code-owned binding instructions,
fits the unchanged complete-request ceiling while preserving all three results.
The large source/question remain unchanged. Another nonduplicate three-result
fixture still exceeds the ceiling and is refused without content removal.

Current historical-pair tests normalize only these explicitly verified changes:
strictly expand references, require policy equality with the actual native adapter
before removing that added field from the comparison view, and remove only the
exact new code-owned instruction suffix. All other source, native, raw-answer,
journal and cost fields remain compared. Old reports and frozen replays are not
rewritten to match the new wire.

`development_native_reader_policy_amendment` pins only the reviewed runtime file
and complete resulting runtime digest. Restoring that file's old hash must recover
the previous runtime identity. Its history manifest retains the preceding 48 pins
plus the three source-snapshot amendment artifacts. Current validator imports and
three provider-free workflow entry points are retargeted; old paid executors,
packages, grants, scores, result records and historical replay commands are exact.

The prior source-snapshot repair remains present. The old CNY grants remain
closed at zero. Any separately approved new diagnostic still needs its own exact
current package, independently reviewed ordinary inputs and source-first gates;
this repair does not itself activate that authority or certify I02–I06.
