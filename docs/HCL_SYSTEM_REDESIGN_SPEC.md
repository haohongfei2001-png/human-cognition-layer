开发中每个worker独立worktree；共享契约提案由单一维护者做有版本的兼容修改，不为每次接口缺陷另建总体计划。运行中只读Snapshot→Delta→唯一commit，验证读集与ACL epoch，相关冲突局部重算；CAS冲突不是重复收费调用的理由。

## A／D. 完整问题清单与解决映射

### A.1 证据边界与根本诊断

本轮只恢复会影响设计的状态，没有重跑全部历史实验或重新评分。补读的源码确认了几项不能归结为“输入格式”的问题：

`action_explanations.py` 主要从有限目标生成知情选择、缺乏知情和机会限制等固定解释；`appraisal.py` 主要消费显式感受和目标评价；`character_development.py` 只比较单来源中两个相反行动、明确日期和特定改变表述。这些限制意味着：即使语义入口完全修好，开放解释、情感动力和长程人物理解也不会自动出现。[R05–R07]

`argument_analysis.py` 的固定论证句式、最多三个拆分前提、被记录而未实际检验的类比，与根目录 `quantified_logic.py` 中已经存在的真实 FOL/反模型求解形成脱节。问题是精确工具与开放语义之间缺少完整连接，不是“项目完全没有逻辑计算”。[R08–R09]

共享状态也不是已经完全统一：`workspace.py` 调用旧 v1 准备路径，多种 `answer` 回调各自处理输出；部分领域另建工作空间。H03/H05 有真实依赖，但入口和组合模式受限。统一改造必须消除这些运行分叉，而不是给它们加一个共同名称。[R04,R12–R14]

问题类别的含义：**确认缺口**表示当前代码中尚无目标所需的一般能力；**确认故障**表示真实运行已有失败记录；**架构冲突**表示接口/语义不能满足共同目标；**工程风险**表示需设计与测试覆盖，但没有据此宣称已经发生泄露或数据损坏；**研究未知**表示没有充分效果证据；**计划缺陷**表示进度与研究目标失配。

### A.2 根因归并

一是将语言解析、领域表示、具体算子输入句式绑在一起，导致无关语言变化关闭认知计算。二是多数机制偏向证明“不能推出什么”，但缺少发现解释、生成预测、比较模型和作出正向判断的算法。三是源权限、人物视角、推断假设和代码依赖没有足够清晰的独立语义。四是统一入口没有统一执行图、状态与交付责任。五是全量目录和审计载荷占用模型资源，工程格式开始反向定义能力。六是建设、真实功能与效力结论在管理上虽有标签区别，却没有形成有效的交付闭环。

## B. 最终完整技术架构

### B.1 先定义必须计算什么

HCL 的外部目标不是产生一份更长分析，而是在开放输入下完成以下闭环：识别事件与歧义；提出新的解释与局部模型；执行逻辑、心智、行动、情感、概念或规范计算；让它们消费同一组相关状态；经反证和时间更新修订；形成有根据、有主次、可修改的回答或判断。

强基础模型承担开放语言、候选发现、背景知识与表达。HCL 承担状态转移、假设环境、局部求解、证据与模型比较、跨领域结果消费、反事实和资源控制。允许外置可训练编译器或控制模型，但不要求改动基础模型内部权重。系统不依赖公开隐藏思维链；可审计的是实际 HCL 运算和可见模型输出。

### B.2 一套系统，不是一种万能推理规则

共享认知表示包含：Source/Evidence、Entity/IdentityHypothesis、Event/TemporalConstraint、Proposition/Frame、Perspective、Hypothesis/LocalModel、Inference、Issue、Norm/Commitment、AnswerClaim。词句原文和解释保留自然语言版本，可计算部分另有类型化 AST；不能形式化的内容保留为 `OpaqueMeaning`，并标出尚未检查的关系。

共用内核包含：作用域与访问检查、版本化事务、假设环境、反向依赖、事件时间和记录时间、冲突传播。逻辑结果、概率结果与论证接受状态共用身份和证据，但不能互相偷换语义：

- 逻辑算子输出“在假设 A 和规则 R 下可导出 q／有反例／未知”。
- 概率算子输出“在模型 M 下、使用这些观察因子的分布或区间”。
- 论证算子输出“在明确优先关系下，该论证被接受、受攻击或未决”。
- 开放语义算子输出“基于这些材料的可挑战解释判断”，不是定理。

同一个来源观察只注册一个观察因子；重复转述通过来源关联组处理。规范权重不能成为事实概率；模型多次同意不能成为独立证据。各种结果进入同一输出必须携带各自的适用条件。

### B.3 六项必须写入代码的结构不变量

**源文不可被解释覆盖。** 读取组件给稳定 SegmentID、原文范围和版本；模型不手算 Unicode 偏移。源文中包含的命令只作为数据，不改变规则或权限。

**ACL 与人物接触分离。** `principal/access_policy/access_epoch` 决定系统能读取什么；`agent/received_at/understood/believed` 表示人物认知假设。权限许可不证明人物知道；人物知道某事也不自动赋予系统读取私人来源的权利。

**时间不是单一时间戳。** `event_interval`、`agent_access_interval`、`recorded_at`、`narrative_order`、`concept_effective_interval` 分别保存。相对时间用差分/先后约束求解；旧伪日期只能迁为 LegacyOrder。

**所有解释均可被修订。** 指代、同义、因果方向、规范适用和人物身份对齐都能成为假设，不能只允许最终结论修订。重算同时追踪新证据与缺证据默认。

**结果不能脱离被使用的输入。** 每个操作声明实际 `read_set`、假设、结果字段与下游消费；“两个 JSON 放在一起”不能充当跨能力依赖。

**正式交付只有一个出口。** SDK、CLI、异步、流式和兼容入口都进入相同 engine。未经过 HCL 的第三方自行调用不在本系统保证范围内；内部不允许隐蔽 Base 旁路。

### B.4 公共接口规格

以下是要实现的接口契约，均为提议，不是当前已存在 API。内部值类型采用 Python 3.12 支持的 dataclass/枚举及版本化 JSON Schema。具体第三方包版本由实施时锁文件确定，不在本稿凭记忆指定“最新版本”。


|接口|签名|关键契约|
|---|---|---|
|`HCL.run`|`async run(request: TaskRequest) -> TaskResult`|唯一正式事务入口，验证权限/状态/预算，绑定一次任务，最终只返回经AnswerContract核对的结果；同步SDK使用同一async engine的同步适配。|
|`HCL.stream`|`stream(request: TaskRequest) -> AsyncIterator[DeliveryEvent]`|先发状态事件；关键主张审查后才发布对应文本，未知结论不可提前流出后假装能撤回。最终TaskResult沿用run语义。|
|`SemanticCompiler.compile`|`compile(snapshot, source_segments, issue, model_gateway) -> ParseDelta`|保留不同读法和原文锚点；仅提出解释，不能写source_report或修改SourceHandle。|

| Perspective | agent_id、nested_path、at_time、observation_model、belief_model、source_evidence | 不包含系统读取授权；内层肯否不得从外层自动脱离 |
| Hypothesis | explainandum、latent_assignments、premises、predictions、counterpredictions、model_id、coverage、unmodeled_flag | 必须能说明预测什么；不能只存“自私/善良”标签 |
| InferenceResult | kind、values、assumption_environments、premise_ids、counterevidence_ids、model/rule_version、coverage、diagnostics | 必须明确 EXACT_MODEL／APPROX_MODEL／DEFEASIBLE／SEMANTIC_JUDGMENT 等语义 |
| OpResult | operation_id/version、read_set、effects、result_refs、issues、resource_usage、diagnostics、candidate_delta | 无写库/网络/交付权限；状态提交由 engine 完成 |
| Delta | base_revision、access_epoch、created/retired hypotheses、new inference edges、query_dependencies、read_set | 不可覆盖来源；校验中断不能提交一半 |
| AnswerClaim | text、claim_id、used_result_fields、support_envs、counterevidence、epistemic_status、materiality | 精确引句合法不能代替解释正确性 |
| TaskResult | answer、claim_records、status、unresolved_issues、execution_receipt、usage、state_revision | 部分完成、缺证据、预算不足和故障分别标记 |

`LocalModel` 的 AST 只允许声明变量、有限域或分布族、时间转移、观测因子、前提效果、严格/可撤回规则、效用或论证关系、查询和干预。它不能导入 Python、读文件、联网、修改规则仓库或从评测读取答案。数值求解在限制 CPU、内存和迭代次数的进程中运行。每个模型含 `domain_assumptions`、`fit_residuals` 和 `unmodeled_observations`，无法解释的原始事件不能被丢掉以通过校验。

### B.6 六个关键计算内核的具体算法

#### 假设维护与不动点

对规则 `p1 ∧ ... ∧ pk → q`，从每个前提的环境标签选择 Ai，合成 `A = rule_assumptions ∪ A1 ∪ ... ∪ Ak`。删除含已知 nogood 的环境，再保留包含关系下的最小支持环境。多条独立规则形成 OR 支持；同一环境内所需成员是 AND。撤回 b 只删除含 b 的环境，不能把独立支持 c 也删除。[S01]

硬矛盾、可撤回冲突和人物自相矛盾分开处理。严格求解在明确模型中执行；全部知识库不采用爆炸原则。时间展开的图优先按拓扑增量计算；真的递归组用强连通分量、受限不动点或对应求解器处理，循环本身不能产生无根支持。预算化裁剪保留 `UNEXPLORED_ENVIRONMENTS`，不能据保留分支全同意就声称完全证明。

还须记录查无证据时依赖的范围。例如“尚无甲接收消息记录”的结论依赖一个 `AbsenceWatch(agent=甲, message=m, interval=t, source_scope=R)`；R 新增相关记录时，这个默认必须重算。索引缺项不等于世界上没有信息。

#### 开放假设与模型发现

初始输入是需要解释的观察 E 和问题 Q，不是正确答案。候选者提出 `(M,H)`；本地执行得到各观察的相容性、预测和未解释项；形成残差集合。编辑器针对残差选择增添变量、分离身份、改变接收时间、加入不同目标或应对策略、替换因果方向或概念读法。再执行，而不是让候选者重复“想得更深”。

候选保留按解释覆盖、反证承受、预测差异、结构复杂度和估计成本作 Pareto 束；同义但预测相同的解释合并。未知真解释是否进入候选集合必须作为独立失败类型。校准良好的有限模型可以使用后验；未校准语言相容分只用于探索排序，不能输出成精确心理概率。AutoToM 的自动模型发现和逆向推理提供部件依据，本系统不将它的负熵目标作为唯一正确性指标。[S02]

#### 心智、行动和情感的共同局部模型

人物 i 在 t 时刻的估计可表示为 `P(B_i,t, G_i,t, Z_i,t | observations, M)`：B 是其信念，G 是目标，Z 是习惯、注意、错误或其他策略候选。显式有限任务可通过枚举或变量消元求解，较大状态可用粒子近似，报告粒子有效数和覆盖，而非假装精确。

候选行为策略为 `π(a|B,G)=Σ_z w_z π_z(a|B,G)`；理性分量用 `π_r(a)∝exp(β Q(a;B,G))`，其他分量必须有自己的可执行定义。Q 从行动前提/效果图通过有限动态规划或 rollout 得到，不由模型一句“此行动很合理”直接替代。β 与 w 是局部参数；没有校准时报告敏感性区间，不将最优行为假设强加给所有人。

情感不是行为后的标签。对每项目标 g 计算 `desirability_g = E[U_g(after)|B] - E[U_g(reference)|B]`，同时计算预期差、可控制行动、主体归因和身份/规范关系。候选应对方式改变后续注意、可用行动或评价，而不是直接修改原事件。动态评价可借鉴 EMA 的评价与应对分工，但不能声称算出了人物的真实感受。[S03]

#### 跨时变化解释

对一系列行动/自述/情境，比较至少三类实质不同模型：稳定目标下知识或机会变化、角色/策略变化、目标/价值本身发生变化。用分段似然或约束违背成本加变化点复杂度，寻找候选分段；没有可靠概率时使用支配关系和可撤回论证，不编造数值。

模型必须对变化前后和反例均给预测；“价值变化”不得仅靠一项新选择获胜。角色、领域、受众和自述变化各有独立变量。系统可给有依据的倾向和最强替代解释，不被固定 `NO_WINNER` 限制。

#### 哲学、概念和规范的可执行部分

逻辑前端保留量词、否定、模态和概念版本，分别编译竞争读法。Z3 等求解器的 UNSAT 只针对已声明编码成立；返回的 unsat core 默认不能称最小，只有完成逐项缩减或相应优化才可作最小性主张。有限域找不到反例不等于一般有效；已有独立反模型评估器应保留。[R09,S04]

论证构造由前提、严格/可撤回推理与结论组成；攻击分为 undermining、undercutting 和 rebuttal，优先关系明确后形成 defeat 图。默认计算 grounded 扩展；有决定性多解时有界探索 preferred 等分支，输出接受范围。语义攻击成立与否仍是可挑战判断，不以图求解取代语义理解。[S05]

概念候选除定义还包含典型/边界/排除例及用途；类比使用关系映射，求一对一候选对应、关系一致性及高阶结构支持，再审查关键不相似点。迁移结论必须回到目标域验证，不能靠表面相似直接复制。[S06]

规范框架内先求可行动作集合和冲突约束；明确权重可进行多目标/稳健优化，权重未知时计算 Pareto 支配和结论所需的价值优先序。跨框架稳定的理由与真正分歧分开。允许有理由的推荐，不把“没有唯一道德 gold”变成永不判断。

#### 文学与长程理解的计算

材料有 story graph 与 discourse graph 两种关系：事件先后、人物接触属于前者；倒叙、焦点化、声调、重复、反讽和留白属于后者。算法先提取可观察形式差异，再由解释候选说明它如何改变读者可得信息、期待与评价；逐段查证并检索最强反例。

审美解释不能简单由“更多特征/更强情绪”打分。以明确标记的对照改写检验假说：保持事件不变而改叙述顺序或重复句，观察原解释是否还成立；对照生成只是分析工具，不是原作证据。主题假说需要解释形式与内容的共同模式，且能容纳反向段落。长程跨章人物变化由 M09 提供实际模型，不靠每章摘要拼接。

长期材料通过外存按需读取，参考 RLM 的输入外置思路；检索必须包括支持、挑战和替代解释三条查询通道。输出的是当前记录的充分论证包和覆盖范围，不声称语义上穷尽全文所有可能联系。[S07]

### B.7 完整认知机制规格

下面每项明确输入、算法、输出、交互、新增能力、实现及边界。M 编号用于定位测试，不意味着每次请求都运行所有机制。输入和参数由预算配置调整，不把有限工程初值定义为心理学上限。


#### M01｜开放语义编译与按需精化

**输入：** 原始文本/表格转写、问题、SourceHandle、历史实体候选和Frame；输入不包含答案标签或人工正确心理状态。

**实际计算：**

1. 读取工具产生稳定段落/句片ID及精确原文，模型只引用ID，不手算字符偏移；源文不可被模型覆盖。
2. 先抽事件、施受事、命题、模态、量化和相对时间，保留未解析原文；中文名、多词名和代词均使用实体候选ID。
3. 生成竞争ParseDelta：条件作用域、否定范围、引述层、讽刺读法、指代身份分开；明确区分direct_report、interpretation、background_prior和assumption。
4. 执行类型/来源/跨度检查；语义义务检测遗漏条件、时点、主体或反证。模型的反向释义与独立对照只产生AlignmentJudgment，不能把候选升级为源文事实。
5. 认知计算暴露决定性未绑定前提时，产生RefinementRequest回到有关段落；局部重编译，不重提取全部材料。
6. 多个解释共享证据根但有独立假设环境；同义与same-as关系同样可被反例撤回。

**输出：** ParseForest、EventDelta、AlignmentJudgment、未解析区域Coverage、需要进一步理解的Issue；含原文与每项增删解释。

**如何整合：** 为全部算子供公共IR；时间冲突、反例和文学解释可反馈重编译；语义改动触发M02重算。

**新增能力：** 从识别固定自述转向开放语义、多语言、歧义保留和反向修正；无需一开始精确形式化全文。

**实现位置和方法：** hcl/semantics/{segments,compiler,alignment,frames}.py；JSON Schema约束输出+dataclass内部值类型；类型化树中允许OpaqueMeaning叶子，不允许eval任意文本。

**资源与能力边界：** 当前工程默认每轮至多8个解析候选、每Issue最多3次无进展精化，均可按预算调整；未覆盖区域必须保留，不宣称一般语言已被形式证明。

**交付位置：** S2开始接入，S2主要完整交付；验收T01, T02, T03。当前仅设计，未作HCL效力验证。


#### M02｜假设环境、作用域桥接与非单调增量推理

**输入：** 证据根、公共命题、明确/可撤回规则、时空/人物Frame、规则优先级、SourceRev与AccessEpoch。

**实际计算：**

1. 把事实支持、因果影响、论证攻击和时间约束分为不同边类型，不用一种依赖边代替全部语义。
2. 每个结论保存最小充分假设环境L(q)。AND规则对输入环境作兼容并集，OR保留独立路径；冲突环境nogood不参与可用结论。
3. 用正负支持两位与论证接受状态保留矛盾；人物自身矛盾不导致全局爆炸。严格逻辑只在一致的明确模型环境内运行。
4. Bridge包含源/目标视角、实体对齐、时点映射和所需假设；系统ACL先过滤，人物能否接触消息另由M03判断。禁止直接取消Scope限制。
5. 维护反向依赖、源变更读集、检索QueryDependency和AbsenceWatch。新增或撤回材料同时更新正证据与缺证据默认，未检索到不等于不存在。
6. 对变更影响的强连通分量求受限不动点，重新求解论证/概率子问题；无关分量保持语义哈希不变。

**输出：** 带环境标签的结论、冲突集、失效/保留路径、ChangedClaims、未展开环境和修订解释。

**如何整合：** 所有算子用同一核心提交；概率后验、逻辑推导和规范接受分别存标签，不相互偷换。

**新增能力：** 不仅拒绝旧状态，而是保留替代支持、局部撤回、跨视角安全组合及新增反证传播。

**实现位置和方法：** hcl/kernel/{types,truth,scope,temporal,revision}.py；事件溯源+逆向索引；ATMS式集合用bitset/共享环境；预算化懒展开；不预建全世界。

**资源与能力边界：** 环境数最坏指数增长。超限返回FRONTIER_UNEXPLORED；有限搜索失败非证明。默认结果为skeptical与conditional两层，不能把有根支持当真实性。

**交付位置：** S2开始接入，S2主要完整交付；验收T03, T19, T22, T24。当前仅设计，未作HCL效力验证。


#### M03｜事件驱动的多人物/高阶心智推断

**输入：** 事件/传递/观测图、人物初态、观测与信任候选、查询视角链、时间约束和默认假设。

**实际计算：**

1. 编译事件的可见性、实际接收、理解和相信为不同变量，私信接收不等于其他人知道发生了接收。
2. 对显式有限模型执行逐事件世界转移；对人物视图执行观测过滤与信念候选更新，不给人物逻辑全知。
3. 需要时用有限可能状态或粒子近似追踪各人的belief；受限的信念持续规则附无更新/无遗忘假设，遇新证据可撤回。
4. 按问题惰性展开B_a(B_b(p))等路径，保留外层否定、内层否定、未知、二者都有的区别；去除无关递归。
5. 以观察、消息和行为反证修订当前估计；迟到记录只改变分析者对过去的估计，不反写当时人物可得信息。

**输出：** 时点化MentalState、视角差异、有限模型中的知识/误信预测、支持环境和剩余可能状态。

**如何整合：** 供M05行动模型、M07沟通、M08评价、M14责任共同消费；更新使用同一认知变量ID。

**新增能力：** 不仅解析“我认为”，可从消息路径与事件推导隐含信息差和错误信念，且可检验视角不污染。

**实现位置和方法：** hcl/operators/epistemic.py；小状态精确枚举，较大状态有界粒子/状态合并；动态认识论式事件更新仅在声明局部模型内。

**资源与能力边界：** 默认嵌套深度按问题需要，运行profile可伸展；达到资源界限需标明未展开，不称无限阶。现实人物推断保持模型条件与有限注意可能性。

**交付位置：** S3开始接入，S3主要完整交付；验收T04, T05。当前仅设计，未作HCL效力验证。


#### M04｜残差引导的解释与局部模型发现

**输入：** 要解释的观察/选择/文本现象、当前候选、预测残差、反例、可用背景知识与预算。

**实际计算：**

1. 建立Explainandum而非直接生成答案：明确哪些事实/行为/文体现象需要被解释。
2. 模型提出假设程序，包括潜变量、必要前提、因果/动机联系、预测、可能反证；相似措辞且预测等价的候选聚类。
3. 构建Observation×Hypothesis矩阵，记录已解释、矛盾、未解释及来源组；至少保留一个非主流可行解释和unmodeled余项。
4. 残差定位后应用明确模型编辑：补观测通道、改时间范围、替代目标、加入习惯/误解/机会因素、拆分身份、切换概念读法。编辑只改局部候选，不修改事实。
5. 在保留的开发材料上比较预测相容性、反证承受、解释覆盖与复杂度。用Pareto束而不是单一置信度最大化；重复假设不增加证据。
6. 寻找区分性问题或观测；有预算时调用独立候选者，没预算时保留候选覆盖不足。

**输出：** HypothesisPrograms、PredictionMatrix、模型编辑历史、区分性证据需求和候选覆盖边界。

**如何整合：** M05/M08/M09/M11/M13可调用同一发现器，但各自规定预测义务；M06/M12可构造反例。

**新增能力：** 由固定三种条件解释升级为此前未枚举的机制/动机/文本解释发现；用可预测差别去除文字重述。

**实现位置和方法：** hcl/operators/abduction.py + hcl/semantics/model_compiler.py；受限AST包括latent、observe、transition、constraint、predict；beam默认12/每轮新增4，仅工程初值。

**资源与能力边界：** 没有校准似然时不输出伪后验；复杂度惩罚不能把不常见但有证据的解释删除。无法穷尽假设是显式状态，不是停止研究该能力的理由。

**交付位置：** S3开始接入，S3主要完整交付；验收T06, T07, T13。当前仅设计，未作HCL效力验证。


#### M05｜目标—行动—动机的逆向规划与混合策略推理

**输入：** 人物信念、目标/子目标候选、行动与可选行动、资源机会、代价、角色规则和行动历史。

**实际计算：**

1. 建立有限行动图及前提—效果，区分世界可行与人物认为可行；计划意向与实际行为分开。
2. 对候选目标和信念，用动态规划/A*或有限rollout计算行动价值Q；在局部模型中使用softmax理性策略并与习惯、误操作、机会约束策略作混合。
3. 用行动与沟通证据更新候选权重；同一观察因子注册一次，源转述相关性不独立相乘。
4. 记录哪个行动在什么目标下可解释、机会限制是否排除候选、混合动机是否必要；对错误行为不强制改写为最优。
5. 新消息改变信念后重算相关计划预测；比较目标改变、信念改变和策略改变能否解释行为转折。

**输出：** 候选意图/目标、行动预测、反证、竞争原因、识别不充分与模型内概率/排序标签。

**如何整合：** 使用M03心智、M07承诺与M08情感调节；向M09变化点与M14责任提供同一行动时状态。

**新增能力：** 不仅检查“动机前提没矛盾”，而是产生行动预测、排除不适用模型并比较可行解释。

**实现位置和方法：** hcl/operators/agency.py；策略π=Σ_z w_z·π_z，其中理性项π∝exp(βQ)，其他项显式定义；β/w只用开发校准，不声称人类通用常数。

**资源与能力边界：** 行为不足以唯一识别奖励/信念；保留等价策略类和未识别状态。强模型评分是未校准软信号，不当外部观测。

#### M06｜复杂逻辑、局部因果与反事实计算

**输入：** 多读法命题树、严格规则与默认规则分离、局部因果结构、问题和干预。

**实际计算：**

1. 只把可表达部分编译为逻辑树；保留量化、作用域与模态边界，不以字符串替换确定等价。
2. 复用FOL/有限反模型，并增加约束/SAT/SMT求解；分别返回证明、已检验反模型、局部无解、unknown或超时。
3. 对因果模型执行abduction–action–prediction：先约束背景，再替换被干预机制，最后传播；观察条件化与do干预不混用。
4. 反模型回译为具体情景，让语义编译器核对是否仍满足原文，而非仅满足错误形式化。
5. 矛盾返回unsat core；最小性需要另行缩减验证。保留多个一致假设环境，不能从矛盾推出任意结论。

**输出：** FormalResult/Countermodel/InterventionResult、模型和翻译假设、受影响变量及有效范围。

**如何整合：** 支撑M03、M05、M12、M13、M14；模型失配反馈M04而非删除原始事件。

**新增能力：** 将已存在但隔离的正式逻辑接入普通问题；补足反事实、因果识别及反例驱动修正。

**实现位置和方法：** hcl/operators/logic.py、causal.py；hcl/quantified_logic.py提取有限解析/验证资产；使用已固定版本Z3，规则层保留独立witness checker。

**资源与能力边界：** 一般FOL不可保证总终止；bounded-unsat只对该域有效。没有可识别因果模型时只报告条件情景，不能给现实因果证书。

**交付位置：** S2开始接入，S2主要完整交付；验收T08, T09, T15。当前仅设计，未作HCL效力验证。


#### M07｜语用、策略交流、承诺与共同理解计算

**输入：** 话语事件、说话者与受众视角、候选意图、字面内容、承诺/规则和互动历史。

**实际计算：**

1. 区分字面命题、言语行为、暗示、目标受众及共享背景；沉默/含糊回答保留不同解读。
2. 对候选交流策略预测受众会如何理解；有合格局部模型时可采用受限递归说者—听者推断，否则保留条件论证。
3. 承诺生命周期计算条件、接收、接受、履行、违约、撤回；共同理解需要分别建模解释和确认，不以共同听到替代。
4. 比较误报、故意说假话、真话误导、隐瞒和非策略误解；知情/目标缺失不得强判欺骗，但可以给证据支持的倾向。
5. 三方以上合作使用个体计划与授权边，评估谁拥有哪一项责任和选择，不建全知群体。

**输出：** InterpretationDistribution/偏序、CommitmentState、误解来源、可行澄清行动、共同理解的有限阶结果。

**如何整合：** 向M03提供消息观测，向M05提供策略动作，向M08/M09提供伤害及修复事件，向M14提供承诺与条件。

**新增能力：** 从特定英文承诺链升级为开放话语下的语用推断、策略比较与互动更新。

**实现位置和方法：** hcl/operators/interaction.py；事件状态机+受限消息博弈/论证；承诺状态和个人解释分别持久化。

**资源与能力边界：** 无需穷尽所有交流策略；真实人的理解不能由“消息发出”认证；授权属于源中制度模型，不等于系统权限。

**交付位置：** S3开始接入，S3主要完整交付；验收T05, T11, T19。当前仅设计，未作HCL效力验证。


#### M08｜情感生成解释、应对与再评价

**输入：** 人物belief/goals、事件预期及结果、控制机会、归因、自述和外显行为，含互相冲突目标。

**实际计算：**

1. 按人物信念估计事件对每个目标的可取性、预期差、控制可能、主体归因和规范/身份相关性；形成有来源的评价剖面而非一个情绪分数。
2. 候选情感解释由剖面、先前情感与应对策略共同生成；多个目标可产生混合情绪，外显笑/哭只是一种观测。
3. 比较问题导向、回避、重释、寻求支持等应对模型对后续注意/行动的预测，不把候选应对当人物已实施。
4. 新知识/目标修订后重算评价；区分分析者重释与人物本人再评价；时间过程参数在开发集校准或只给定性状态。
5. 保留自述、观察和推断三通道，检查情感标签是否解释了关键差异，而非以名称代替机制。

**输出：** AppraisalProfile、EmotionalHypotheses、CopingAlternatives、再评价差异及矛盾/不确定性。

**如何整合：** 与M05双向耦合但经版本控制：情感可能改变行动策略，行动结果又改变评价；使用有限时步迭代防循环。

**新增能力：** 能解释为什么同一事件产生不同/混合感受以及为什么后来改变，而不只是列出报告过的情绪。

**实现位置和方法：** hcl/operators/affect.py；借鉴EMA的评价—解释分工，核心为显式目标后果计算+候选语义映射+时间更新；不照搬为人类心理定律。

**资源与能力边界：** 无临床诊断或唯一内心状态保证；参数不充分时输出条件方向与竞争解释，不伪装精确情绪测量。

**交付位置：** S3开始接入，S3主要完整交付；验收T10, T19。当前仅设计，未作HCL效力验证。


#### M09｜关系、身份、角色和价值的长程变化推理

**输入：** 同一人物/关系在多个事件中的行动、承诺、知情、能力、评价、自述和角色背景。

**实际计算：**

1. 关系按有向人物对×领域×评价维度建模；信任能力、善意、可靠履约分开，不能自动对称传播。
2. 候选模型分别解释违约原因、道歉/补救效果和预期变化；接受道歉或恢复信任必须有独立证据。
3. 角色要求、本人认同、他人归因和实际行为独立存储；计算同一时点角色义务冲突及可行调和动作。
4. 对跨事件数据比较stable-preference、belief-change、opportunity-change、role-pressure、strategy-change、value-change模型；以分段动态模型/变化点检测寻找转折。
5. 价值变化候选需解释多情境行为和反例；比较拟合及结构复杂度，不将单次选择反演成稳定权重。

**输出：** DomainRelationshipState、IdentityNarratives、ChangePointCandidates、变化解释及未变化维度。

**如何整合：** 共享M03/M05/M07/M08变量；变化点影响后续预测但不覆盖历史角色/概念，传给M11人物弧线和M14判断。

**新增能力：** 突破一章、两行动和显式“我变了”限制；真正比较知识、情境、价值和身份变化。

**实现位置和方法：** hcl/operators/relationships.py；有界分段模型搜索/动态规划，支持参数区间和无参数论证版本；结果逐人物情境隔离。

**资源与能力边界：** 没有跨情境证据时不强判稳定性格；变化点只是候选，叙事可靠性和身份对齐同样是依赖。

**交付位置：** S3开始接入，S3主要完整交付；验收T11, T12, T27。当前仅设计，未作HCL效力验证。


#### M10｜长期材料检索、反证闭包与持续认知

**实现位置和方法：** hcl/memory/{store,index,retrieval}.py + hcl/kernel/revision.py；SQLite WAL事件账本、内容寻址原文、可重建检索索引；对象原子写后再提交引用。

**资源与能力边界：** 记录图闭包不是全文/世界语义完备证明；未读章节不得声称已读；删除的隐私内容不得因不可变日志而永远保存。

#### M11｜文学叙事、修辞、主题与审美解释

#### M13｜哲学论证、反例和反思性概念判断

**输入：** 问题、论证候选、事实/定义/价值前提、严格与可撤回规则、读法和反对意见。

**新增能力：** 从固定because句式整理升级到推理规则检查、论证攻击、反例发现和有根据立场。

**资源与能力边界：** 论证接受是给定框架内的结果；不以多数模型投票判真理；哲学题可有多个合理立场。

#### M14｜伦理、价值权衡与复杂行动判断

**输入：** 可选行动、后果模型、人物知情/控制/意图、权利/义务/承诺、角色和用户认可或分析者提议的原则。

**实际计算：**

1. 提议并标明规范框架；用户采用、人物赞同、制度声明和分析者临时条件分开。无需用户预写某种固定英文合取规则。

**新增能力：** 从给定规范的因素检查提升为情境化规范构建、冲突处理、方案生成与复杂判断。

#### M15｜统一计算图、资源控制与跨能力执行

**输入：** TaskRequest、共享Snapshot、认知Issue、算子IO/effects/成本契约、模型能力与任务预算。

**实际计算：**

1. 必经接入建立源范围、任务义务与状态版本；简单请求可用本地/轻路径，不能调用无关检查凑次数。
2. 根据所需判断反向展开缺失前提，再前向执行可满足前提的算子；优先复用已存在推导与索引。
3. 模型只提交计划提案；引擎验证读写集、前提、权限、资源和局部AST。按需提供相关契约，不推送完整目录。
4. 对独立分支并行计算Delta；唯一提交者校验read_version与access_epoch，冲突则只重算相关分支。费用调用不可因提交冲突自动重发。
5. 一次新事件或模型修改更新M02依赖队列；跨域共享变量，不能将同一因素再次当独立证据。
6. 预算内允许精化/修复/换局部模型；使用可解释优先级和校准的预期收益估计，禁止以信心/低熵单独作为正确性。
7. 精确no-progress键含Issue、模型版本、输入版本和操作；停机返回完成/部分/待证据/预算/失败等不同状态。

**输出：** ExecutionTrace、已解决/未决义务、带来源结果、消费记录、资源账目及ResumeToken。

**如何整合：** 它不是独立认知收益的替代品；负责真正调用M01–M14和M16，使共享推导实际进入结果。

**新增能力：** 取消UniversalHCL与H03/H05两套运行链、固定三工具两调用和单供应商容量限制。

**实现位置和方法：** hcl/runtime/{engine,planner,context,budget,recovery}.py；模型调用仅经hcl/models/gateway.py；图节点具typed effects，不生成任意执行代码。

**资源与能力边界：** 局部程序与solver有wall/fuel/memory上限；模型目标是建议不是授权。SDK无exactly-once保证时保留UNKNOWN不重发。

**交付位置：** S1开始接入，S5主要完整交付；验收T19, T20, T23, T25, T28。当前仅设计，未作HCL效力验证。


#### M16｜反思诊断、回答承诺与持续算法学习

**输入：** 候选回答、逐主张推导、未决Issue、原文、操作记录、开发反馈、冻结评估信息边界。

**实际计算：**

1. 形成AnswerContract：每个关键结论绑定支持环境、反证、推断类型和有效范围；模型生成自然表达不需暴露隐藏思维链。
2. 程序检查可验证的引用/版本/数值/结果ID；语义审查检查主张是否超出推导、是否遗漏关键反证与合理解释。二者分开记证据等级。
3. 发现问题归类为表示错误、候选遗漏、局部模型错设、计算错误、检索遗漏、表达失败或不可识别；调用对应修复而非泛泛再反思。
4. 同状态保留多条可辩护结论；部分结果可以交付，但不可忽略已知决定性冲突。源文中的指令不能修改可信规则。
5. 从开发轨迹学习编译/候选/调度/评分器，用反例和跨域验证防自我强化；新策略版本离线/受控验证后晋升，单次推理不得自行改全局代码或规范。

**输出：** JudgmentBundle、AnswerText、ClaimSupportMap、诊断标签、局部改进样本和版本化策略候选。

**如何整合：** 所有算子都接受诊断反馈；后期独立比较隔离在evaluation层，gold不得进入模型或永久记忆。

**新增能力：** 由引用合法即交付，升级为计算结果真正约束回答、错误定位和可持续改进。

**实现位置和方法：** hcl/runtime/answer.py、hcl/learning/{datasets,training,policy_registry}.py、hcl/evaluation/{runner,scorers}.py；训练可选小模型，不依赖更改强底座。

**资源与能力边界：** 语义审查并非证明，必须用独立对照检验；训练与收费运行需未来授权，已暴露材料不得用于独立确认。

**交付位置：** S1开始接入，S6主要完整交付；验收T26, T30, T31, T32。当前仅设计，未作HCL效力验证。

### B.8 统一执行过程与局部恢复

引擎的逻辑流程如下；这是行为规格伪代码，不是本轮提交的实现：

```text
RUN(request):
  admit(request, principal, task_budget)
  snapshot := load_session_snapshot()
  issues := interpret_task_and_existing_state(request, snapshot)
  if lightweight_obligations_sufficient:
      result := local_compute_or_one_model_call_via_gateway()
  else:
      while unresolved_material_issues and budget_remaining:
          plan := backward_expand_requirements_then_schedule_ready_operations()
          proposals := execute_independent_operations_on_snapshot(plan)
          check(types, frame, premises, access_epoch, rules, actual_read_set)
          commit_or_rebase_only_nonconflicting_delta(proposals)
          propagate_changed_variables_and_absence_dependencies()
          if representation_gap: refine_source_segments()
          elif model_mismatch: revise_local_model_not_source()
          elif no_progress: change_justified_strategy_or_stop_with_reason()
  contract := assemble_claims_from_actual_result_fields()
  answer := realize_natural_language(contract, gateway)
  validate_mechanical_obligations_and_material_semantic_claims()
  bounded_local_repair_if_authorized_else_partial_or_failed_result()
  return one_version_bound_TaskResult
```

模型不是先看 40 个详细契约，再决定选三个。控制器根据 Issue 要求反向展开前提，并从索引获得有关操作说明；本地规划可以选择有限查找、求解、假设扩展、改读法、回源、审查等动作。关键结果已有缓存时不再让模型重写一遍。

选择操作依据预计解决哪项问题，以及质量收益、信息价值、成本和延迟；初始使用可解释规则与校准排序器，后期学习，不假定能直接获得真实 VOC。硬预算与权限优先。循环的无进展键含 Issue、来源/模型版本、算子和已得结果；同一解释反复更自信不能算进展。

#### 四种路径

本地确定路径可以零模型调用；轻路径一次模型调用但仍做任务/范围/状态检查；局部认知路径可采用编译—执行—表达；深度路径按问题持续多步骤计算。两阶段是可能的执行结果，不是系统定律。

没有源文的哲学问题可以使用明确假设与标记背景知识。不得将“无来源”“不可识别”“语义编译失败”“预算不足”“模型故障”统一成证据不足。复杂问题存在决定性冲突时，不能静默回退为忽略冲突的普通回答。

#### 运行故障处理表

| 故障 | 本地处理 | 是否可重新调用模型 |
|---|---|---|
| 结构无效但完整返回 | 保存原返回；按具体字段做确定性检查或请求最小修复 | 只在本任务已批准修复预算内，记新调用而非抹掉旧失败 |
| 语义缺项/错位 | 指向具体段落、条件、主体或时点重新对齐 | 可，不能用修改源文使其适配 |
| 模型与真实事件冲突 | 保存事件，产生未解释残差并修改候选模型 | 可，受预算与迭代上限控制 |
| 求解器超时/unknown | 保留已验证局部结果和未决变量，选择另一算法或缩小当前子问题 | 可选；不把未找到反例写成证明 |
| 请求容量不足 | 生成更紧凑论证包、按需分解或调整已允许的模型端口；保留来源可访问性 | 必须先重新核算；不能丢决定性反证 |
| 网络发送结果未知 | 保留成本占用与未知状态；使用供应商支持且语义明确的查询/幂等机制核对 | 不支持核对时禁止盲目重发 |
| 并发状态变化 | 校验 read_set，安全的不相关变化重基；相关变化仅重算受影响部分 | 不因提交冲突自动重复已收费调用 |
| 权限撤销 | 取消未来读取/发送，失效缓存与派生输出；已发送事实如实记录 | 不能以旧token或旧缓存继续 |
| 部分主张无法成立 | 移除/改为明确限定或保留分歧；仍可交付其他独立成立主张 | 有必要且预算允许才修复，不一律整篇拒绝 |

预算是任务级账本，所有并行分支共用上限；消费前原子预留，记录 estimated/reserved/observed/unknown，不能用未知费用当零。超时停止等待不保证供应商已停止计算，不声称 exactly-once 网络语义。

每次上下文构造依据端口真实容量，预留系统说明、任务、关键源片段、局部推断及输出空间。精确 tokenizer 不可用时采用保守估计与余量，记录估计方式。UTF-8 请求字节、上下文 token、本地状态规模、输出 token 和费用分别限制，不用一个 36KB 值替代全部。

#### 交付影响的强制检查

`AnswerClaim.used_result_fields` 必须记录最终判断实际使用了哪项运算值。例如使用 `intentional_exploitation.requirements.knowledge_at_action=false`，而不只是“调用 M05”。干预测试改变该值及其上游证据后，相应结论必须改变；与之无关的引句不得变化。程序检查只能证明数据连接；语义是否合理仍需独立功能审查和后期消融。

自然语言是默认外部输出，引用和不确定性按需要呈现。结构化内部 JSON 不是强迫用户使用固定四字段答案的理由。流式状态事件可以即时发送；会影响结论的文本在审查前不得不可逆发布。已发布内容随后发现错误，必须发明确更正事件，不假装从未交付。

### B.9 一条贯穿多领域的设计演算

以下为本稿新写的工程情景，未调用模型，也不是评测成绩。

一部戏中，演员青只听到导演说“演出将延期”；原话其实是“如果场地检测失败，演出将延期”。编剧宁在检测通过后照常发出演出通知。青认为宁违背承诺，说“果然，所有人的声音都被听见了”。后来日志证明，宁发通知时尚不知道青听到的是删掉条件的版本。青当时也尚未看到该日志。

公共表示应产生：`promise_condition=test_failed`，`actual_test=passed`，`Qing_received=unconditional_delay`，`Ning_knows_distortion_at_notice` 有两个时间假设，`ironic_reading` 与字面读法并存。信念持续默认支持青此前期待，但依赖其未获澄清的限定范围。

M03 计算青、宁的不同信息状态；M07 对照原承诺与接收版本；M05 比较“宁明知误解而利用”“宁按原条件行事”“宁有转述核验疏忽”等解释；M08 比较落空期待、被排除感与其他情感解释；M11 检验讽刺读法如何通过“所有”与实际遗漏造成反差；M14 分开计算故意利用与核验义务。

新日志加入后，若来源与时间读法成立，`knowledge_at_notice=false` 使“明知而利用”的必要条件失效，但不自动排除疏忽；青未接触日志，其当时的愤怒和失信判断不自动改变。原条件承诺的有效判断也不被青接收的版本覆盖。

文学解释仍不能直接等同于人物心理。讽刺句可以体现受伤、控诉、表演性反击或叙述策略；M11 必须结合前后语调、受众和重复来比较。将该句改为“我的声音没有被听见”的对照，只用于检验原句形式效果，不变成原作证据。

如果再改变规范前提为“负责通知的人有义务主动核实所有关键转述”，角色责任可能增强；事实知情变量不因此变真。这个变化同时展示了：心理、行为、情感、文学与规范使用共同变量，但不同结论保留不同推断语义。

### B.10 学习与持续增强的具体位置

### C.2 数据迁移与回滚的固定程序

**建立边界。** 以批准时 main 和设计摘要固定兼容面、源版本和旧接口清单。现有运行时归档继续按原身份保留；旧数据可读不代表需要旧生成入口继续对外运行。

**抽取纯运算。** 将旧机制中的实际计算与源解析、模型调用和消息拼装分离。符合新语义的算法保留，通过显式 LegacyAdapter 导入旧输入；不兼容的算法用同一行为测试改写。新任务不能偷偷触发旧 provider callback。

**写入旁路数据副本，不双主写。** 旧持久资料若存在，先只读导入新的迁移命名空间；生成 old_id→new_id 对照和逐项语义记录。导入幂等，当前源版本、历史版本和被撤回记录分别保留；不得直接覆盖旧库。没有统一旧数据库时，迁移器接收各旧类型快照，不能伪造一套旧DB结构。

**保留旧语义，不升级证据。** `SUPPORT_AVAILABLE` 迁为“存在有效推导根”，不迁为真实；旧 model alias 不变不可变模型快照；旧 UTC 伪时间迁为 SOURCE_ORDER；旧 source-local name 不自动成为跨文档 Entity。无法完整转换的记录进入 quarantined/legacy-only 区域，列明不可用原因和可恢复字段。

**同一入口下对照。** 新 engine 可以执行隔离的旧纯算子和新算子做离线差异对照；不能默认双跑付费模型。差异分为预期语义扩展、旧Bug修正、新回归、表示变化和未决，不要求把错误旧答案复制成新正确答案。

**原子切换。** 完成全域综合与迁移验收后更新正式导出/配置指针。兼容类名最终都委托同一 engine，停用旧直接生成入口；历史包仍可在只读、无凭据环境分析。

**失败回滚。** 代码、schema、规则与索引版本共同固定。回滚运行指针到先前受控版本，不能用旧代码写新schema，也不能将新推断降格回旧事实。新版本产生的事件保留隔离日志，明确哪些可重新投影。恢复之后先验证权限、来源版本和预算账本再开放调用。

**删除和审计的冲突。** “历史实验不可改写”不等于用户私人数据永不删除。公共实验既有原始包保持原样；运行时私人材料按授权删除原文、向量、缓存和派生状态，只保存许可范围内的非敏感墓碑/审计。已发往供应商的请求无法靠本地删除撤销，应如实记录。

## E. 统一可执行研发计划

### E.1 固定依赖与安全并行

整体依赖为 **S1 → S2 → {S3 ∥ S4} → S5 → S6 → S7**。S3 与 S4 的完整功能同等重要，文学/哲学/伦理不是心理模块有了效果之后才允许开发的附件。

S1/S2 负责后续工作的共同类型与可信执行地基，不代表重新采用上一轮“先跑一个小实验，再决定是否扩展”的 P0 顺序。两条领域线从初始实现就用唯一入口和真实数据对象持续集成，S5 是全面融合与切换，不是第一次发现接口无法互通。

一个核心维护者拥有 `kernel`、公共schema、gateway权限和存储迁移。领域人员只在自己的 worktree 修改算子与对应测试；接口改动通过带版本的提案交由维护者合并。跨线程依赖由版本号和读集协调，不能让两个 writer 直接改共享分支或同时写数据库。

阶段内采用职责清晰、可回滚的完整变更集合。一个PR可包含同一功能所需的代码、测试和文档；规模太大时按稳定接口边界拆分，而不是按每个Bug或每个证明文件拆分，也不强制“一阶段只能一个巨型PR”。

### E.2 阶段完成与进入条件

每个阶段标注 IMPLEMENTED_OFFLINE、INTEGRATED_OFFLINE、LIVE_FUNCTIONAL；它们不互相冒充。进入后续依赖安全的开发以稳定契约和必要离线行为为条件，**正式完成该阶段仍要有实际模型普通输入的功能证据**。缺授权时保留状态并继续允许的独立工作，不反复造批准包装、不谎称完成。

T19、T27 等跨阶段验收采用明确切片：S3 的联合更新要求三类计算，S5 才验完整五类跨域；S4 验自然长文与反证回源，S6 再验完整压力规格。阶段适用切片不等于整个验收族已完成。


### S1｜统一内核、正式入口与可迁移数据主干

**完整功能目标：** 在原仓库中建立唯一正式入口和可信状态/调用主干；旧功能可被受控调用，新模块能用同一公共协议开发。

**可复用资产：** core来源/支持规则、workspace版本、既有真实实验原始归档、计费边界和正式逻辑工具。

**依赖：** 用户批准后的main基线与固定目标。

**安全并行：** 核心维护者拥有kernel/types、scope和公开接口；不接受并行writer直接修改。；端口/账本、迁移/兼容、测试/manifest可在冻结接口后并行；算子团队可写测试和pure prototypes，不直接写共享schema。

**测试族：** T20, T21, T22, T24, T28, T29, T30。只验公共入口、一个旧算子接入、源版本/ACL/预算/提交与迁移的核心切片；不要求未来全部领域完成。

**退出与验收：** 公开入口的轻任务和至少一个旧认知操作在同一engine中实际运行；迁移/回滚与预算故障通过。进入真实功能完成需新批准的真实模型调用，离线只能记INTEGRATED_OFFLINE。

**阻断处理：** 未获收费授权时继续离线核心/领域开发，不反复创建批准包装；不给S1标记LIVE_FUNCTIONAL；独立分支不因effect未知停工。

**可复用资产：** semantic原文锚定、scope不干扰、quantified_logic反模型、evidence_closure反证和修订见证。

**依赖：** S1。

**安全并行：** 语义与多语言；假设/时间/作用域核心；形式求解与反例；上下文/恢复；共享类型变更由核心维护者按版本合并。

**测试族：** T01, T02, T03, T09, T20, T21, T22, T25, T28。完成多语言、相对时间、跨源身份候选、反模型回译、缺证依赖和动态调用；S3/S4的共同类型接口可用。

**退出与验收：** 在真实自然输入中从解析→计算→主张输出跑通，含跨源、非显式时间、至少一次假设撤回和反模型回译；schema成功不算闭环。

**可复用资产：** B–E有界纯计算、信念/声明区别、行动时条件、承诺回放、Appraisal和关系不泛化边界。

**依赖：** S2。

**安全并行：** 心智/动作/因果；交流/承诺/共同理解；情感/应对/关系动态；联合scenario由集成owner持续维护。

**阻断处理：** 一次比较无增益不删领域；定位候选、模型、状态或表达问题并改进同一机制；理论不可识别的样例正确保留多解。


### S4｜长程文学、概念哲学与伦理复杂判断

### S7｜独立验证、跨模型效力与科研/榜单成果

**完整功能目标：** 对完整能力和最有价值的子机制取得可公信的增益、归因、迁移和目标赛道成果。

**改动范围：** 冻结任务分布/配置/强比较器、按来源聚类分析、语义与格式分评、机制/组合消融、多个预算档、权威规则审核和允许的提交。

**可复用资产：** 全部已有事实/失败留存；开发与封存隔离；统一runner与manifest。

**依赖：** S6。

**安全并行：** 独立评测/评分；迁移与预算前沿；方法论文/复现包；领域缺陷回流至相应机制；禁止为赢榜反向砍功能。

### E.3 统一测试、CI 和实验体系

批准后只保留一份 canonical 技术规格、一份结构化 manifest 和一份生成的执行状态视图。README 是入口索引；DEVELOPMENT_PLAN 是当前依赖队列；STATUS 是证据摘要。Master Plan 旧目标和历史记录保留，但明确哪些执行规则已被新规格替代；三份文档不再重复复制几百行实验结案。

CI 分层而不是为每次实验新增 workflow：快速类型/契约/纯算子/变更影响测试；集成与性质测试；发布候选全回归、迁移和故障测试。已消费历史包以固定版本做哈希完整性与必要重放，不因当前运行时改变而重写历史 pins。构建缓存按源码/规则/依赖版本隔离。

真实模型功能与效果实验使用一个统一 runner、一套调用账本、一套来源曝光记录和同一个公共入口。批准可针对明确任务、调用/费用上限、输入集合及允许修复方式形成有限 campaign，不要求每一小次运行都重建授权源码和workflow。新供应商、超预算、隐私披露和正式提交仍需另外批准；本稿不生成任何付费权限。

研究失败分类固定为：编译/语义错位、候选遗漏、模型错设、计算错误、检索遗漏、跨域消费失败、表达失真、资源或transport故障、任务不可识别。记录归属到现有问题/机制条目，修复具体原因，不在每次失败后另造一份战略计划。

对于 #323–#325：批准后做一次旧增量与当前主线比较，保留仍有价值的提示边界或预算回归；SID001 已经执行，保留其原始包并核对是否有可见语义结案，不重跑、不复用旧余额。完成处置后关闭被替代Draft，不能把“未合并”误说成“未运行”。[R02]

### E.4 创新研究进入工程，而不是永久 deferred

每个研究性机制仍须交付可运行的第一种算法、明确失败诊断和可替换接口。按误差分解比较两个实质不同实现：例如假设生成缺失就比较候选策略，信念更新错误就比较局部状态模型，文学解释单薄就改善形式—意义关联与反例流程。可以用免费离线性质和已暴露开发材料反复调试，但必须标明证据等级。

路线改进不必每次征求新目标批准。只有改变用户固定目标、跨越预算/隐私边界、移除关键能力或变更重大设计原则才升级决策。普通算法替换、接口修复、合理拆PR、CI和merge恢复由工程负责人处理。

## F. 完整验收矩阵与科研成果路线

### F.1 验收等级

**DESIGNED：**本稿已有方案；不是实现。

**IMPLEMENTED_OFFLINE：**代码和免费离线检查通过。

**INTEGRATED_OFFLINE：**正式入口、真实本地算子、共同状态与交付通过可控后端联通；人工stub不能证明模型会产生正确候选。

**LIVE_FUNCTIONAL：**批准的真实模型从普通输入进入相关机制，产生正确的计算/更新并影响最终输出；只证明该功能范围，不是独立效果。

**EFFECT_CONFIRMED：**在相应任务分布、模型和预算范围内，公平比较、归因、迁移与不确定性支持研究主张。

### F.2 建议的验收数值及其边界

以下是本方案的初始验收设计，不是行业标准、已达到结果或一般认知上限。批准时可一次性微调；不能看效果后随意改阈值。

| 验收层 | 建议准则 | 不能推出什么 |
|---|---|---|
| 确定性逻辑/状态/权限/迁移性质 | 已声明有限模型与故障规格中的必须性质全部通过；失败必须修复 | 有限测试全部通过不证明开放世界无错 |
| 各领域真实功能 | 每个领域至少30个独立开发情景，包含自然中文/英文或明确记录覆盖缺口；关键推理义务达到90%，严重源/人物/时间错位为0/审查样本；正向推断与不必要拒绝分别评分 | 不是30次成功截图，不是题数完成率，不证明全域普遍90% |
| 全域联合 | 至少三种不同结构情景族，每族既有正向计算也有干预/非干扰变体；覆盖5类以上计算；每项指定变化与保持全部可追溯 | 不能用一种模板的改名样例冒充多类结构 |
| 运行有效交付 | 发布候选按来源/调用情景分层估计，目标有效交付≥99%；完整报告样本量与区间 | 不得用一次烟雾成功宣称99%可靠 |
| 简单任务 | 至少不新增一次默认专门规划模型调用；对目标机器报告本地额外p50/p95和语义非劣性；非劣界建议1个百分点 | 不承诺所有输入零开销，不把低成本优先变成关闭认知 |
| 规模 | 100k与1M字符档、100/1000事件、12/40活跃人物作工程压力规格，另行验证自然长文理解；批次和模型预算记录 | 字符容量不是阅读理解质量，也不是固定产品最大值 |
| 研究效力 | 完整系统相对合格强比较器具有预声明的实际有用改善；报告配对效应、家族聚类区间、错误类型与费用前沿；可沿用原计划10个百分点等作为追求目标而非事后切换门槛 | 不把P值、格式合规、单个模型或少量评分点变成广泛科研成功 |

领域尚未达到功能准则时继续其实现和改进，不改成可选。不存在唯一gold的文学/哲学领域用可核验事实、论证义务、合理异读、形式分析、反例和有理由判断联合评审，不能只奖励与评审者价值观一致。

### F.3 机制、表达与入口的诊断拆分

两类输入：原始普通输入；经人工核对的事件/时间/显式陈述。三类系统：强通用工作空间、可靠状态推理、完整HCL。在测试隐含信念时，不得给“人工核对输入”附正确隐藏信念。进一步oracle中间态只能单独用于定位，不能列为端到端成绩。

记录编译正确性、候选覆盖、模型拟合、计算正确性、反证召回、下游消费与最终语义。若中间结果正确却答案错误，改交付；若候选中根本没有可行解释，改发现；若同等事件表示下计算仍失败，改机制，不能继续只修入口。

机制消融保留相同来源、合理基础表示和预算。H-flat 切断跨领域依赖而非删原文；候选发现、状态转移、模型推断和表达分别可消融。跨模型先测端口兼容与普通输入功能，再测相对该模型强配置的独立效力。

### F.4 后期科研和权威评测

完整能力达到系统研究水平后，S7 冻结配置、独立校准来源、强Base/强提示/强通用脚手架以及合格简洁比较器。报告不同预算档、模型别名与版本证据，不把同alias视为永久物理快照。不将同一个故事的40评分义务当40独立样本。

建造期只审查公开评测的规则元信息，不读封存内容：是否允许外部模块、模型调用数、工具/检索/记忆、跨样本状态、训练数据、输出形式、模型声明和代码提交。若只允许单模型无外挂，则不把关掉HCL所得成绩称HCL成果；另选合法轨道或报告研究对照。

本稿不预定一个尚未核实当前规则的榜单，也不以榜单反向删除领域。科研主张可以是开放语义可撤回推理、反证跨域传播、解释/模型联合发现或跨模型系统效力；使用ATMS、SMT、EMA、结构化论证等本身不是原创贡献。[S01–S07]

已曝光材料可做新版本开发和回归，但每次结果单独保存；旧结果不重写。sealed材料由独立读取面与人员/角色控制；基于元数据的拒绝必须先于内容加载，禁止全面历史grep或打开所有blob寻找“是否泄露”。本轮未访问封存材料。

## G. 面向 Codex 的正式工程交接

批准后将本规格、manifest和明确的用户修订一次性固化到同一仓库。Codex 从最新main核对变化，按S1–S7依赖实施，而不是重新设计目标或要求用户逐项给下一条任务。

详细交接见 `CODEX_HANDOFF.md`。其中规定批准校验、源码读取范围、文件ownership、接口版本、阶段拆分、真实功能与免费测试的区别、历史包隔离、收费权限、故障恢复及完成报告。批准本方案不等于自动授权任意付费实验、公开私人材料或榜单提交。

普通实现问题由Codex依据规格决定；涉及H中重大选择、不可解决的新安全边界或用户授权范围变化时才提交差异。发现设计局部不足，更新对应接口/算法条目并保留理由，不以小Bug另起宏大计划。

## H. 用户最终微调的重大设计决策

固定目标、全部领域覆盖、允许可撤回的隐含推理、单一正式入口和跨模型模块定位，不再作为“是否做”的问题重新询问。下面仅给对实现上限与长期行为有重大影响的选择。每项已有可实施的推荐默认；未更改就按推荐执行。


|决策|推荐默认|其他方向及代价|需用户微调范围|
|---|---|---|---|
|D1 开放推断的认识论配置|允许可撤回默认和隐含推断，可靠虚构/现实记录/思想实验采用明确不同的适用条件。|仅显式状态的方案更保守但无法完成固定完整目标；因此不推荐作为最终系统。|可微调真实人物判断的谨慎程度，不改变开放认知能力建设。|
|D2 最高质量与成本的优先关系|默认balanced，保留deep研究档；每次有明确token/调用/费用/时间预算，不以两次调用或36KB固定能力。|固定深推理提高成本与延迟；固定低预算容易让复杂领域得不到实际计算。|批准研究/日常不同的资源包；本轮不设真实付费金额。|
|D3 可训练侧模型|S6保留完整训练/校准接口与数据闭环；先可运行的通用语义端口，再依实际需求训练编译/候选/控制侧模型。|先训练专用大模型可能提升拟合却增加数据和迁移成本；纯提示永久冻结也会限制可优化空间。|训练投资和模型资产可公开范围；完整能力不以训练能否获批为借口删除。|
|D4 复杂价值判断的输出立场|给有理由的独立推荐，公开采用的规范与最强反对意见；事实与价值分歧分别处理。|只列观点缺少判断力；单一固定道德评分会掩盖条件与价值选择。|可指定优先原则；未指定时系统不得冒称是用户价值。|
|D5 长期人物推断的保存策略|按人物/领域分层、可修订、可删除；原始资料、解释和策略经验分库；不形成不可撤回的全局人格标签。|全不保存限制持续理解；全量画像长期保留会放大误判与隐私风险。|默认保存范围、敏感数据保留时长和导出权限。|
|D6 局部模型生成的权限|允许受限类型化程序与可校准混合模型；不得生成任意网络/系统代码或在线修改可信规则。|完全固定模型更窄；无约束代码灵活但难以保证隔离和可重现。|是否未来开放额外求解插件；普通AST/校验细节由工程负责人决定。|


## 技术评审结论与边界

本方案为当前确认的重大问题提供了具体处理方式，并把完整目标覆盖到实际算法、代码迁移、阶段和验收。它不承诺在任意有限材料上唯一识别人类真实心理，不把逻辑一致当作道德真理，不声称开放语义已获数学证明，也不保证这一实现已经达到全局最优。

这些边界不是削弱目标：它们要求系统能够给出有根据的正向推理与判断，同时保留真实不确定性。算法研究和能力建设继续，效果主张等待相应证据。

**批准后的执行依据是这一套规格及其manifest，不是再回到“每发现一个问题就重新决定项目下一步”。研究目标不变；允许变更的是更好实现这个目标的具体算法和工程结构。**
