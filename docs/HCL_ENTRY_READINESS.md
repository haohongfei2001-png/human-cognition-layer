# Optional source-bound entry blockers

The [single semantic smoke](HCL_SEMANTIC_SMOKE_20261007_RESULTS.md) reached relevant
B01 processing and a complete answer, but still selected a rejected D02 operation
and a B02 reader with no checked access result. This slice supplies the first
planner with a small code-owned `literal_entry_blockers` group, bound to the exact
source ID and version, for known necessary B02/D02 input conditions.

The checks are intentionally incomplete:

- B02 reuses the existing complete-source fragment splitter and the very same
  compiled speech/receipt/availability/address regex objects. An unparseable
  boundary or unmatched whole fragment is a known blocker for the current access
  entry. It does not run the access checker, create aliases, or compute views.
- D02 reuses only the `CommunicationScene` constructor's mandatory source-layout
  bounds. It does not pre-run a scene view. Valid doubt-only treatment remains
  possible even where a receipt-bearing view would not be supported.
- Absence of a blocker is not readiness, semantic relevance, evidence, a native
  invocation, checked treatment, receipt or comprehension. Later conditions can
  still fail. The planner remains responsible for useful selection and arguments.

No source is rewritten, candidate invented, operation deleted or automatically
rerouted. Selected operations still enter the real existing native path and retain
its receipt, insufficiency result or rejection. Complete original text remains
available for model reasoning. Source/model/result strings cannot supply these
code-owned observations or promote themselves to system instructions.

## Capacity and unchanged admission

The group and its explanatory policy are optional together. With no blocker the
original message object and bytes are unchanged. If the full augmented request
would exceed the existing 36,000-byte wire limit or caller context limit, the entire
new group is omitted and the original complete messages are returned unchanged.
Original content is never trimmed or normalized, and an originally oversized
request is still refused. This does not silently shrink evidence to make it fit.

The existing request serialization was extracted into a pure helper shared by the
port and this fit check. It constructs no client, reads no credentials, contacts no
provider and touches no reservation ledger. Port client validation, exact request
hash/quote admission, fixed 16,384/high planning, 8,192 final and retries remain
unchanged. The previous smoke's original 30,529-byte request and hash still match;
with the optional group it is 31,171 bytes (+642). Final messages are not enlarged
by this metadata. Exact 36,000-byte controls retain their original admissibility.

Provider-free controls cover authentic prior input blockers, independent literal
access, negation/later receipt, legitimate blank-line B02 paragraphs, D02 doubt-only,
multisource/version isolation, forged source fields, an unflagged later actor-limit
failure, source changes during planning, preserved real dispatch and insufficiency,
whole-group capacity omission, original overflow rejection and identical old request
hash/fee quote. These scripted controls do not show that a model makes better choices.

The 142 historical pins and exact closed-tree 112-test smoke replay preserve all
consumed studies and their original source-first disposition. All model budgets
remain closed. Any new live validation needs a new bounded approval; no efficacy,
production-readiness or I02–I06 advancement is claimed.
