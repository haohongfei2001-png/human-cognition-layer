# SID001: source-inference synthetic diagnostic freeze

## Status and purpose

**PREPARATION ONLY. No paid execution is authorized or implemented.** This is a
separate dependent package after runtime PR #323; it does not change HCL runtime,
merge that PR, create a grant, add a live provider trigger, or run a model.

The proposed experiment asks whether v25's source-inference delivery instruction
changes unsupported explanatory claims, compared with both the strong Base and
archived v24, without suppressing explicit source-reported mental content. It does
not test native benchmark accuracy, ordinary external task utility, general HCL
competence, human morality or final independent efficacy. More provider-free tests
cannot establish those behavioral outcomes.

The twelve cases are original fictional adult-character prose from a separate
fixture-authoring worker that did not inspect runtime code, prior benchmark cases
or answers. This is separation of author and implementer roles, not human authorship,
independent model families, statistical independence or independent writing systems.
All sources, questions and criteria are development-exposed and permanently consumed
for final confirmation before any proposed model output. Public/native-source task
validation remains a separate unmet goal. Nothing is presented as a sealed holdout.

## Fair arms and exact model input

Each case has three frozen arms:

1. Strong Base receives the complete source and question plus the common JSON answer contract
2. H_v24 uses the Git-certified DRC008 archived runtime to prepare the same source/question
3. H_v25 uses the candidate runtime from PR #323 to prepare the same source/question

H_v24 and H_v25 receive the same common answer contract after their preparation.
No case ID, expected answer, rubric, source-state hint, caller premise or manual
mechanism routing is transmitted. Sources retain exact bytes, source identity and
version. A provider-free assertion requires v24/v25 user/source/checker payloads and
checked-treatment presence to match; the policy instruction is the deliberate delta.
Any actual absence of checked treatment is recorded without disqualifying the case.
All three arms use the same underlying DeepSeek V4 Pro alias, high thinking mode,
JSON mode and 8,192-token maximum output. No extraction, retries or model judges.
Execution order rotates the three arms evenly across the fixed twelve-case order.
No provider snapshot identity is inferred from its returned alias.

`PACKAGE.json` freezes each complete request and its digest, runtime/archive hashes,
source/rubric hashes, prices, code and documentation hashes, call count and prospective
costs. The code contains no transport function, provider SDK, credential acquisition,
grant or execution CLI. Even an existing provider credential or consumed grant does

## Blinded source-first review and frozen decision rules

After any separately authorized run, prepare review packets containing only the
complete source, question, frozen rubric and three shuffled opaque answer labels.
Do not show arm identities, execution order, model/cost metadata, treatment receipts
or the allocation map to the reviewer. Save complete judgments and their hash before
revealing arm identities. The current package has no outputs and does not claim an
actual blind review has occurred. Answers must never be edited or regenerated for
review convenience; invalid, truncated or failed answers remain recorded.

Judge meaning rather than literal phrase overlap. For each opaque answer record:

- Source-report preservation: PRESENT, PARTIAL, OMITTED or UNCERTAIN for every required proposition
- Unsupported promotion: NONE, MINOR, MAJOR or UNCERTAIN, with the exact answer claim and relevant source evidence
- Alternative handling: ADEQUATE, UNSUPPORTED_EXCLUSION, OVERCAUTIOUS or UNCERTAIN
- Actor/source/time handling: CONSISTENT, MISMATCH or UNCERTAIN, with evidence
- Overall explanation: SOURCE_BOUNDED, MIXED, UNSUPPORTED or UNCERTAIN

An explicit self-report or third-party attribution may be accurately reported;
its existence must not be erased simply because sincerity/private truth is unknown.
An action/outcome alone does not supply a stable trait or uniquely true motive.
Reasonable hypotheses may be offered as hypotheses with their missing premises,
without treating the absence of evidence as disproof. A source's explicit testimony
or fictional event report is distinct from established real-world psychology.

Primary reporting counts major unsupported promotions or actor/source/time
mismatches and paired changes in required-report preservation. Minor defects,
uncertain judgments, refusals and format/citation failures are reported separately.
Uncertain semantic judgments stay unscored, with their denominator shown. Exact
source quotations or a correct broad lesson cannot certify the whole explanation.
No automated phrase scorer, moral-truth grade or retrospective rubric change is used.

Disposition after review is KEEP_FOR_FURTHER_VALIDATION, SIMPLIFY, REMOVE or
INCONCLUSIVE, justified by the raw paired evidence and all incremental H costs.
These are development decisions, not statistical significance or general efficacy.
If v25 merely adds caution/length without reducing unsupported claims, or suppresses
explicit reports, its instruction overhead is a reason to simplify or remove it.
Native-source validation remains necessary even if this diagnostic is positive.

## Review correction: sealed-object identity after rename or copy

Independent review found an inherited source-history helper defect: raw Git log
used abbreviated object IDs, while content inventory used full IDs. A protected
blob renamed to an ordinary path could therefore miss the object-identity guard.
A synthetic-only regression reproduced the problem. Metadata-only inspection
confirmed the pinned baseline's 44 protected blobs still carried protected path
names, so this exact source receipt did not expose sealed content.

The current `i02_exposure_history_v2.py` helper requests full object IDs with
`git log --no-abbrev`. Three new
synthetic tests cover default abbreviation, rename and copy, and fail immediately
if the protected synthetic object's content-read command is attempted. Current
history/snapshot/firewall/archive/runtime-validation helpers are pinned alongside
the protocol. The exact baseline history receipt remains unchanged after the fix.
No real sealed source content was used to reproduce or repair the guard.

The legacy helper bytes are preserved because consumed Gilman/James/Gaskell
execution packages pin them. SID001 imports only the corrected v2 audit. Fresh
source work must use v2; v1 remains for historical reconstruction and is not a
renamed-source safety guarantee. This scoped migration does not pretend that every
old caller has been rewritten or that historical qualification was upgraded.
Direct legacy holder tests can refuse current-runtime hash drift; their certified
archive replay is the historical check. The Gaskell certified replay passes its
16 tests and preserves the historical runtime rather than changing old pins.
