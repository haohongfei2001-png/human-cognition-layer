# S4 bounded concept-version classification and judgment

This additive M12/M13/M14 slice is **INTEGRATED_OFFLINE_PARTIAL**. It preserves
all M01–M16, S1–S7 and T01–T32 obligations, including open semantic alignment,
real-model functional acceptance and effect research. The finite candidates are
injected through an offline candidate port from ordinary Chinese and English
source passages into `HCL.run`/`HCL.stream`; they are conditional interpretations,
not measured extraction accuracy, authenticated preferences or moral truth.

## Versioned contract and identities

`hcl-judgment-candidates-2` compiles to `judgment-model-2` and the standard
three-argument `LocalModelOperator`, with one accepted Delta. It retains the
original candidate bytes and every complete source segment, hash, offset,
version and host-created binding. The v1 judgment and structural-concepts
compilers, algorithms, returned values and certificate interpretation remain
available; old durable results are not silently reinterpreted as v2.

A finite concept family uses the host-validated session/principal namespace,
explicit scope and concept key. Equal words in different scopes need not denote
the same concept. A definition version hashes the family's normalized typed
semantic content: purpose, frame, effective time, assumptions, criterion
directions, and positive, negative and boundary examples. Proposal labels,
span locations and unrelated source versions do not change that semantic
identity. A separate execution/evidence fingerprint binds the complete anchored
proposal and source dependencies. Assumption withdrawal changes which content
is usable; it does not rewrite the immutable original definition.

Namespace metadata is compiled by the host, never accepted as candidate-granted
authority. Pure certificate replay reconstructs the exact bound identity and
recompiles the original candidate; runtime verification separately matches the
actual snapshot. A stable semantic hash never bypasses source permissions,
source-version invalidation, governance, erasure or fresh delivery checks.

## Real directional classification

Each definition criterion uses the existing typed anti-unification algorithm,
including repeated-variable correlations and explicit counterexamples. Query
cases are separate ground terms; classification is not a lookup of training
examples. Typed matching is only a pattern result. Its membership consequences
are directional:

- SUFFICIENT: a match supports membership; a nonmatch does not exclude.
- NECESSARY: a confirmed nonmatch supports exclusion; a match does not establish
  membership.
- BICONDITIONAL: the explicitly proposed conditional definition supports both
  directions.
- TYPICAL: matching records resemblance but produces no normative membership
  premise.

Negative examples, boundary examples, unknown cases and contradictory criteria
remain distinct. A negative example matching a sufficient criterion challenges
that criterion. A match against a necessary-only criterion is not a negative
counterexample. Exact boundary cases, withdrawn assumptions, missing cases and
incomplete searches retain unresolved possibilities. Conflicting membership and
exclusion support is retained, never voted away. This is source-conditional
classification, not an unrestricted learned law.

## Joint uses and actual downstream computation

Explicit use sites select an immutable version or a named finite version choice.
All uses of a shared choice take the same version in a branch. Pairwise allowed
version constraints filter the joint Cartesian product before classification.
Independent marginal version results are never assembled into a fictitious
joint world. Limits are 16 versions, eight criteria per version, 32 independent
cases and uses, four choices of at most four versions each, 16 constraints and
at most 64 candidate joint selections. Existing term, source, model and output
limits also apply.

Real M03/M05 and M07 are computed once for the bound model and shared unchanged
across concept interventions. `CONCEPT_CLASSIFICATION` facts qualify actual M13
premises, including both polarities and aliases of the same concept atom. All
aliases must share one use; competing unbound aliases and parallel rule-derived
membership are rejected. Membership atoms are scoped by family, definition and
case; rule-applicability atoms retain their distinct identity. Existing UNKNOWN
influence closure keeps affected normative conclusions unresolved.

Each full joint branch runs actual proof/defeat, grounded/preferred acceptance,
permission and M14 value comparison. The output records classification,
per-branch allowable actions, responsibility, recommendations and the intersection
across complete branches. A paired intervention changes just one version choice
while holding the factual model, action graph, priorities and value weights
fixed. It reports semantic classification, judgment and recommendation changes
separately from changed proof/evidence identities. Preferred-extension comparison
uses the set of paired norm-state/permission branches, so proof ordering cannot
manufacture a change and independent marginal sorting cannot hide a real one.
This is not an exhaustive minimal-change-set proof.

## Original commitment meaning

A commitment-scope use must pin its original definition, actual M07 commitment
identity, original terms version and offer time. The compiler checks the source
anchor and the actual consumer; unused purported commitment pins are rejected.
The computed fact includes the original M07 terms. The old scope feeds real M13
rules while the current institutional judgment may select a revised definition.
New versions cannot mutate the old terms, history or scope. Renegotiation needs
a new event/commitment. This implements scope qualification after M07; arbitrary
concept-dependent M03/M07 conditions and cyclic dependencies are not supported.

## Budget, recovery and acceptance evidence

V2 charges actual internal M13 evaluate/preferred/critical solver work against
remaining allowance, in addition to classification, joint branching, downstream
judgment and summary comparisons. V1's historical batch accounting remains
unchanged for certificate compatibility. Units are deterministic algorithmic
work, not CPU-time billing. Any incomplete definition, branch, downstream solve
or summary retains frontier evidence, sets complete false, and withholds an
unqualified robust recommendation.

Tests cover a separate exhaustive directional-classification oracle, repeated
variables, unknown/conflicting/boundary evidence, real recommendation changes,
unchanged original commitments and facts, unrelated definitions/sources,
constrained joint choices, semantic versus trace changes, source/namespace/time/
frame/assumption/nested-result forgery, budget prefixes and claim-field binding.
Interrupted RETURNED/computed/committed recovery does not resend an accepted
call or recompute accepted effects; UNKNOWN retains its reservation. Fresh
revocation and synthetic erasure remain fail closed.
