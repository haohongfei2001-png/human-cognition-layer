## Source, selection and limitations

[PyArg](https://github.com/DaphneOdekerken/PyArg), revision
`f907bac94cbdd663839300b3b7523d4d958ff36f`, MIT license, public ungated.
[PyArg documentation](https://daphneodekerken.github.io/PyArg/) describes its
computational argumentation scope. Attribution: Copyright 2023 Daphne
Odekerken; source LICENSE retained by upstream. This is a research development
comparison on four independently authored static examples, **not a released
benchmark, official PyArg score or fresh efficacy evidence**. It uses no owner
private material. No internal generated examples count as external evidence.

Select the explicit from-scratch, complete-semantics, canonical construction
and full five-node completion author fixtures. Ignore random generator outputs,
canonical frameworks constructed from target extensions, incomplete base graphs
and other completions of the same uncertain-source family. Do not manufacture
eight independent examples from one author's eight completions. These four
examples have four distinct graph isomorphism hashes after exact alias
normalization; three have three nodes and one has five, so coverage is limited.
Order by source hash salt HCL-V10-PYARG-DEV-V01. Alternating grounded/complete
queries are frozen before provider outcomes. No outcome-based selection,
answer balance or difficulty claim. Manifest `eval/v10/pyarg_dev_selection_v01.json`.

The source files were inspected and public unit-test assertions were visible
(e.g. one author's complete-extension illustration). No independent blinded
gold claim is made. The static parser projects only literal Argument/Defeat
constructors, variable assignments and the chosen framework declaration; it
never executes upstream source, reads native assertions or imports upstream
solver/gold values into state. All projected inputs, files and renamed families
are development-exposed and excluded from any future sealed transfer pool.
The 512 internal three-node semantic checks already cover the small graphs'
abstract shapes; these examples cannot be represented as structural novelty.
Native source assertions are not used for scoring. The independent generic
three-valued legality solver computes the requested labels from declared inputs.

Source-only registration precedes semantics/query release. All arms see the
same source declarations, normalized complete graph and explicit formal semantic
contract. The complete graph is an author's static framework, not a conversion
of ordinary debate into a presumed attack relation. Incomplete-source fixture
uses only its explicitly authored complete af1 constructor; uncertain base
knowledge is never silently treated as a complete graph. Placeholder ingestion
times are labelled, not claimed as actual author event chronology.

## Arms, scoring and frozen decision

C is strong direct graph/model/uncertainty instruction. P adds a thin fixed-point,
defense/reinstatement/legality checklist. T receives exact generic tool labels
and HCL source-bound state/calculation. An independent exhaustive three-valued
local-legality solver is a competent generic executable baseline; its answers
must agree with the runtime's separate set-defense computation before calls.
This is one generic tool through the HCL boundary wrapper. Do not pay for
identical D and G readouts or claim architectural superiority from T/C/P.

Same existing deepseek-flash alias, thinking disabled, requested temperature 0,
seed 42, max answer 512 tokens. All requested IN/OUT/UNDEC labellings and a brief
reason <=500 characters. Every node exactly once in every labelling; duplicates,
malformed/truncated outputs invalid. Canonicalization sorts IDs/labellings only;
it does not repair wrong semantics. Compare exact declared-graph labelling
agreement and all pairwise discordances; preserve invalids and reason/result
conflicts. Original assertion/gold values stay out of every model call.

Save an arm-masked per-source reason audit before aggregate comparison: complete
graph fidelity, every attack/defense, cycles/alternatives and conditional scope.
Disclose one-agent review, known provider-free consequences, visible source
annotations and styles that may reveal tool use. Actual state/calculations,
generic labels, every arm input and raw answer/hash are archived.

A development increment requires >=2 P-disagreements/T-agreements, <=1 reverse,
and audited evidence-supported calculations for gains. Otherwise SIMPLIFY to
strong C/P, freeze and leave the examples. Even a positive result supports only
these very small formal author examples. It cannot certify full defeasible
updates, moral judgments, natural-language argument mining, stable current-model
gaps or fresh/general efficacy. Do not tune/retry consumed examples or expand
for p-values. Future disjoint external evidence must be separately qualified.
